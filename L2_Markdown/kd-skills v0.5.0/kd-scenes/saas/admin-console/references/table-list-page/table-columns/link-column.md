## 语义定位

该列是**管理后台表格中的链接列 / 超链接列**，用于承载可以跳转、查看详情或打开资源的文本入口。

它不是普通文本列，也不是操作列。判断依据：

- 单元格主体是可点击文本
- 点击行为指向详情页、资源页或新页面
- 视觉与交互应复用 `KD Link`，而不是自定义蓝色文本
- 如果字段没有真实跳转语义，即使视觉上像“标题”或“名称”，也不应落到本列类型

## 列级结构

```text
超链接列
├── 列头
│   └── 表头文字
└── 内容行 × N
    └── 单元/超链接
        └── Link / KDLink（强调）
            └── 文本链接
```

## 抽离后的列级规范

### 1. 列头

> 通用列头样式（背景、分割线、padding、文字）见 `README.md#通用列头规范`。

### 2. 单元格外层

- 单元格左右 padding：`16px`
- 单元格上下 padding：`12px`
- 单元格底部分割线：使用 `inset box-shadow`、伪元素或等价不占高方案绘制 `1px` 分割线，不使用参与行高计算的真实 `border-bottom`
- 单元格内容垂直居中
- 单元格内部 gap：`2px`
- 单元格内容允许 `overflow-clip`
- 单元格内部只承载链接本体，不额外包裹标签、按钮或卡片容器

结论：

- 超链接列属于**链接型单元格**
- 链接本体必须保留真实语义，优先使用 `<a>` 或业务组件中的 `KDLink`

### 3. 链接本体

当前样本使用 `链接 / KDLink` 组件，属性如下：

- 类型：`强调`
- 状态：`normal`
- 下划线：`false`
- 禁用：`false`
- 前置图标：`false`
- 文案：`文本链接`

链接样式以 `kd-components/link.md` 中的 `Link 链接` 为准：

- 行高：`20px`
- 字号：`13px`
- 默认不带下划线
- 禁用态：`opacity: 0.3`，`cursor: not-allowed`
- 状态切换时间：`--kd-time-fast` → `120ms`
- 内容左右 padding：`0`

### 4. 链接颜色

当前样本作为列级超链接，按 `KDLink` 的“强调”类型处理：

- 默认颜色：`kd-color-text-info` → `#1E5FC7`

说明：

- 如果后续 Figma 样本出现“默认灰色、hover 变蓝”的链接列，应补充为次级链接型单元格
- 表格中的详情跳转、资源名称跳转、外部页面跳转，通常优先使用强调链接

### 5. 图标与外链

当前样本只展示文本，不带前置图标，也不展示外链图标。

仅当链接语义明确需要提示跳转方向时，才允许在文案后追加 `14px` 图标：

- 外链：使用外链语义图标
- 跳转详情：使用右箭头或打开语义图标
- 图标与文案间距：`5px`
- 图标颜色继承 `currentColor`

不要为了装饰给所有链接都追加图标。

> Token 变量完整值见 [tokens-reference.md](../../../../../../kd-foundation/tokens-reference.md)，此处不重复列举。

## 与现有样本的关系

### 与 `图文列.md` 的区别

- `图文列.md` 以信息展示为主，支持主标题和次标题
- `超链接列.md` 的主内容本身就是可点击跳转入口

### 与 `状态列.md` 的区别

- `状态列.md` 使用图标 + 文本表达状态
- `超链接列.md` 使用链接文本表达跳转入口

### 与操作列的区别

- 操作列通常包含多个行级动作，如编辑、删除、更多
- 超链接列通常只有一个字段值，点击后进入详情或资源页

## 可复用实现规则

基于当前样本，可以先形成这些中间判断：

1. 表格字段如果本身可跳转，应优先沉淀为**链接型单元格**
2. 链接型单元格必须使用真实链接语义，不应只用 `span` 模拟
3. 链接列不应被实现成按钮列，也不应使用标签背景承载
4. 是否带图标取决于跳转语义，不是链接列默认结构
5. 不具备真实跳转语义的标题 / 名称类字段，必须退回普通文本列，不得仅保留 hover 蓝色来模拟“可点”

## 当前样本不应被误抽象的部分

- 不应把 `文本链接` 沉淀为固定业务文案
- 不应把强调链接色推导为所有可点击字段都必须强调
- 不应把链接列误抽象为操作列；操作列通常承载多个动作
- 不应因为当前样本无图标，就禁止后续链接列出现语义图标
