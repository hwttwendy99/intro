## 语义定位

该节点不是整列，而是**状态列单元格内部的内容元素原子**。

它负责定义：

- 状态图标
- 状态文本
- 状态颜色映射
- 不同状态值的图标 / 文案组合

因此它应被理解为：

- `状态列.md` 的下游原子样本
- 后续 `状态型单元格规范.md` 的直接来源之一

## 元素级结构

```text
状态元素
├── 状态图标
└── 状态文本
```

核心特征：

- 横向排列
- 图标与文字间距 `4px`
- 整体高度由 `12px` 图标和 `20px` 文本行高共同决定

## 抽离后的元素规范

### 1. 基础布局

- 排列方式：`inline-flex`
- 对齐方式：`align-items: center`
- 图标与文本 gap：`4px`

### 2. 图标容器

- 图标尺寸统一为 `12px`
- 图标描边厚度使用 `kd-stroke-width-icon-regular` / `1px`
- 图标容器自身不带背景，不带额外边框

### 3. 文本

- 字号：`13px`
- 行高：`20px`
- 字重：`400`
- 单行展示

## 状态分组与颜色映射

### A. 成功 / 正向状态

状态值：

- 已启用
- 已激活
- 已通过
- 已同意
- 已恢复

视觉规则：

- 图标：`successful`
- 图标色：`场景/图标/kd-color-icon-success` → `#418F1F`
- 文本色：`kd-color-text-success` → `#347317`

### B. 失败 / 禁用 / 拒绝类状态

状态值：

- 已禁用
- 已拒绝
- 已删除
- 未通过

视觉规则：

- 图标：
  - 已禁用 → `circle_slash`
  - 已拒绝 / 已删除 / 未通过 → `cancel`
- 图标色：`场景/图标/kd-color-icon-red-primary` → `#BF3942`
- 文本色：`kd-color-text-error` → `#BB2726`

### C. 待处理 / 待审核类状态

状态值：

- 待审核
- 待审批

视觉规则：

- 图标：`hourglass`
- 图标色：`场景/图标/kd-color-icon-highlight` → `#E99D00`
- 文本色：跟随高亮语义，当前节点同样使用 highlight 体系

### D. 处理中 / 进行中类状态

状态值：

- 审批中
- 审核中
- 恢复中

视觉规则：

- 图标：`clock`
- 图标色：`场景/图标/kd-color-icon-info` → `#1F69E0`
- 文本色：`kd-color-text-info` → `#1E5FC7`

### E. 中性 / 未启用类状态

状态值：

- 未启用
- 未激活
- 已过期

视觉规则：

- 图标：
  - 未启用 / 未激活 → `circle_horizontal_line`
  - 已过期 → `clock`
- 图标色：`kd-color-icon-secondary` → `#757575`
- 文本色：`var(--kd-color-text-secondary)` → `#6B6B6B`

## 可复用实现规则

### HTML / 前端实现建议

推荐结构：

```text
.status-inline
├── .status-inline__icon
└── .status-inline__label
```

推荐最小 API：

- `value`：状态值
- `icon`：可选，自定义覆盖
- `tone`：可选，允许显式传 success / error / warning / info / neutral

但默认优先策略应是：

- **由状态值驱动图标与颜色映射**
- 不要把颜色和图标完全交给业务散配，避免同义状态表现不一致

## 与状态列的关系

- `状态列.md` 负责列头、单元格外层、行内布局和状态列在表格中的位置
- `状态元素.md` 负责状态值 → 图标 / 颜色 / 文案体系的映射

这意味着后续抽规范时可以自然分成两层：

1. **状态列规范**
2. **状态元素规范**

## 当前样本不应被误抽象的部分

以下信息暂不视为绝对固定规范：

- 所有业务都必须只用这 17 个状态值
- 某个状态永远只能使用当前这一枚图标
- 所有“已过期”都必须使用中性灰而不是 warning

这些都需要更多业务样本验证后，才能升格为强规则。
