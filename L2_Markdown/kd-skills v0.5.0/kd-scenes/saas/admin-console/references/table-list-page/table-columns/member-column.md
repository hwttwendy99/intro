## 语义定位

该列是**管理后台表格中的基础成员列**，用于承载：

- 成员头像
- 成员姓名

它不带标签壳层，不带辅助组织文本，也不带多值集合，是“成员信息”的最基础单元格模式。

## 列级结构

```text
成员列
├── 固定列背景（可选）
├── 列头
│   └── 表头文字
├── 内容行 × N
│   └── 单元/成员
│       └── 内容
│           ├── XS Avatar
│           └── 成员姓名
└── 固定列左右分割线（固定列模式下可选）
```

## 抽离后的列级规范

### 1. 列头

> 通用列头样式（背景、分割线、padding、文字）见 `README.md#通用列头规范`。

### 2. 单元格外层

- 单元格左右 padding：`16px`
- 单元格上下 padding：`12px`
- 单元格底部分割线：`1px solid 场景/线条/kd-color-line-light`
- 单元格内容垂直居中
- 单元格没有额外标签底板

### 3. 内容区

- 结构：`头像 + 姓名`
- 头像与文本 gap：`8px`
- 内容区最小宽度：`112px`
- 内容区外额外有 `py: 2px` 微调

结论：

- 该列属于**裸图文成员单元格**
- 它比“图文列”更轻，因为没有副标题
- 它比“成员标签列”更轻，因为没有 Tag 壳层

### 4. 头像

- 头像组件：`KDAvatar`
- 尺寸：`XS`
- 类型：个人实例
- 形状：circle
- 状态：normal

### 5. 成员姓名

- 颜色：`var(--kd-color-text-primary)` → `#0D0D0D`
- 字号：`13px`
- 行高：`20px`
- 字重：`400`
- 文本容器使用 `flex: 1 1 auto` + `min-width: 0`

## 固定列特征

该样本同时暴露了固定列可选能力：

- 可出现固定列背景
- 可出现左边线或右边线

说明：

- “成员列”本身是内容模式
- 当前组件支持被用于：
  - 非固定数据列
  - 固定左列
  - 固定右列

因此需要拆分理解：

- 成员内容规则可复用
- 固定列背景 / 左右分隔线只在 fixed 场景下启用

## 可复用实现规则

### HTML / 前端实现建议

推荐结构：

```text
td
└── .cell-member
    └── .cell-member__content
        ├── .cell-member__avatar
        └── .cell-member__name
```

推荐样式语义：

- `.cell-member`
  - `display: flex`
  - `align-items: center`
- `.cell-member__content`
  - `display: flex`
  - `align-items: center`
  - `gap: 8px`
  - `min-width: 112px`
- `.cell-member__name`
  - `flex: 1 1 auto`
  - `min-width: 0`

### 组件复用原则

- 头像必须复用 `KDAvatar`
- 不应把成员列误实现成带背景的 tag
- 不应把成员列误实现成“头像 + 姓名 + 组织副标题”的图文列

## 与现有样本的关系

该样本与已有几个样本的区别非常清晰：

- `图文列`：头像 / 图标 + 主标题 + 次标题
- `成员列`：头像 + 姓名
- `成员标签列`：头像 + 姓名 + Tag 壳层
- `成员组标签列`：多成员 / 多组织标签集合

这说明“成员相关列”已经能形成明确层级：

1. **成员列（裸内容）**
2. **成员标签列（单标签）**
3. **成员组标签列（多标签集合）**

## 当前样本不应被误抽象的部分

以下信息暂不视为公共规范：

- 当前列宽 `144px` 作为所有成员列固定宽度
- 当前必须使用固定列模式
- 当前示例中的具体姓名

其中：

- `144px` 更适合作为参考宽度
- 是否 fixed 取决于页面列布局，而不是成员列本身
