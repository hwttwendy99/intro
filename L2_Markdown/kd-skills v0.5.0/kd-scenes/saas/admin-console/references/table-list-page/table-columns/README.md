# 表格列规范

本目录负责管理后台表格的**列级选型**和**单元格承载方式**。表格级规则（行高、框架、滚动、悬停、固定列等）见 `../table.md`。

## 列级结构

每个表格列按以下结构理解：

```text
表格列
├── 列头
│   └── 文案 / 空列头 / 表头控件
└── 内容行 × N
    └── 单元格
        └── 文本 / 图文 / 标签 / 状态 / 控件 / 链接
```

- 列头负责字段识别、排序或菜单入口，不承载行级业务动作。
- 单元格负责展示或编辑当前行字段，不承载表格级筛选条件。
- 列类型应由字段语义决定，不按视觉相似度硬合并。
- 除单选列、复选列、拖拽列、操作列外，业务数据列默认使用 Fill 分配宽度。

## 通用列头规范

所有列的列头共享以下样式，各列样本文件不再重复：

- 列头背景：`场景/填充/kd-color-fill-light` → `#F5F5F5`
- 列头底部分割线：`场景/线条/kd-color-line-light` → `rgba(13,13,13,0.06)`
- 列头左右 padding：`16px`
- 列头上下 padding：`8px`
- 列头内部 gap：`2px`
- 表头文字样式：
  - 字号：`13px`
  - 行高：`20px`
  - 字重：`400`（不加粗）
  - 颜色：`var(--kd-color-text-primary)` → `#0D0D0D`

各列样本的 `### 1. 列头` 仅需记录该列特有属性（列宽、列头文案等），通用属性引用本节。

## 单元格基础样式

- 文本展示型单元格默认使用左右 `16px`、上下 `12px` padding。
- 行内控件型单元格默认收窄左右 padding，用于容纳控件边框和交互热区。
- 窄控制列可以使用固定列宽，例如复选列、单选列、拖拽列。
- 单元格内容必须支持 `min-width: 0` 和溢出截断，避免长文本撑破表格。
- 单元格垂直对齐默认使用 `vertical-align: middle` 或等价结构；禁止为了居中把单元格内容包成固定 24px 高容器。
- 允许换行的长文本列使用正常文本流换行；不允许换行的短字段列使用 `white-space: nowrap`、截断或横向滚动策略。
- 空值统一显示 `-`，并使用次级文本色。
- 不得通过缩小字号、压缩行高来解决列宽不足；应使用列宽、最小宽度、横向滚动或截断策略。

## 列类型选择

按字段语义选择对应列类型。每种类型在下方给出选型要点，详细样本见对应文件。

> 当页面已经确定列类型、并需要在 HTML 预览中落成 `renderRow()` 或等价行模板时，继续读取 [rendering-patterns.md](./rendering-patterns.md)。该文件约束“如何渲染”，避免每页各自拼状态图标、双行文本和操作按钮组。

### 文本展示型列

适用于编号、价格、容量大小、联系方式、邮箱、网络地址、日期时间、地点等字段。

- 默认复用普通文本单元格结构，文本使用表格文本规格。
- 日期时间列保持完整格式文本，不在单元格中拆成日期控件。
- 地点、网络地址等路径类文本使用连续文本展示，不默认拆成多个标签。
- 价格、容量等带单位字段应保留单位语义，但不因此升级为输入控件。
- 邮箱、联系方式、网络地址默认按文本展示；只有具备跳转或拨打语义时才升级为链接型单元格。
- 标题、名称、资源名等字段默认先按文本展示型列判断；只有字段本身承担“跳转详情 / 打开资源 / 进入新页面”的真实语义时，才升级为链接型单元格。

### 链接型列

- 必须使用真实链接语义，不能只用 `span` 模拟点击。
- 超链接列默认不显示下划线；hover 时只改变文字状态色或按 Link 组件状态处理。
- 链接列不等于操作列；链接列通常只有一个字段入口，操作列可承载多个行级动作。
- 是否带图标、下划线、禁用态，应作为链接列变体处理。
- 未命中真实跳转语义的普通文本字段，不得仅因“看起来像标题”或“希望可点”就实现为蓝色 hover 链接。

### 图文信息列

适用于头像成员、业务图标、文件图标、Logo + 文本等图文组合。

- 图标或头像不应被文本压缩，文本区域负责截断。
- 主标题优先保证可读；副标题不足时先截断副标题。
- 文件名图文列可使用文件类型图标 + 单标题结构。
- 成员类图文列可叠加 Avatar、姓名、描述、成员标签等信息，但不应与普通标签列混用。

### 标签与状态列

适用于普通标签、成员标签、成员组标签、风险等级、状态等字段。

- 普通业务标签必须复用 `KDTag`，多标签集合允许换行。
- 风险、等级、优先级等字段属于等级标签型单元格，颜色承载等级语义。
- 状态列通常使用图标 + 文本表达单一状态，不应和多标签集合混为一类。
- 成员标签承载身份或成员信息，不应与普通业务标签合并抽象。
- 标签文案、等级枚举、状态全集属于业务数据，不沉淀为通用规范。

### 行内编辑型列

适用于选择器、文本输入框、数字输入框、开关等可直接修改行数据的字段。

- 枚举值编辑复用 `KDSelect`。
- 自由文本编辑复用 `KDTextField`。
- 数字编辑复用 `KDInputNumber`。
- 布尔启停复用 `KDSwitch`。
- 行内编辑列的禁用、错误、聚焦、展开、加载等状态，应优先沿用对应组件本体状态，不在表格层自定义视觉。
- 只读字段应退回展示型单元格，不保留无交互意义的控件壳层。

### 行选择与控制列

适用于复选、单选、拖拽等不承载业务字段值的列。

- 复选列用于批量选择，首列可出现全选 Checkbox。
- 单选列用于唯一选择，列头保持为空，不放全选控件。
- 拖拽列用于行排序，列头保持为空，单元格只承载拖拽手柄。
- 拖拽手柄必须复用图标按钮，不直接裸放 SVG。
- 控制列不混入编号、状态、操作按钮或业务文案。

## 不应被误抽象的内容

- 单个样本的具体文案、姓名、日期、地址、邮箱、价格、容量不进入通用规范。
- 单个样本的列宽只作为推荐或样本值，除复选、单选、拖拽、操作等控制列外，不作为硬性宽度。
- 普通标签、成员标签、状态、风险等级必须保持语义边界，不能因为视觉上都是"小块文本"就合并。
- 展示型文本列和行内编辑型控件列必须分开，不能用只读控件壳层替代普通文本。
- 单元格内的组件必须复用 KDesign 组件语义，不自创表格专用伪组件。
