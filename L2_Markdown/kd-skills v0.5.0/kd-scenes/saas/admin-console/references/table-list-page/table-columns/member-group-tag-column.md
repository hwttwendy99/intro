## 语义定位

该列是**管理后台表格中的“成员组标签列”**，用于承载一组离散的成员 / 组织 / 部门标签，而不是单个标签。

典型数据形态：

- 多个成员标签并列
- 成员标签 + 部门标签混排
- 超出显示数量时使用 `+N` 汇总标签

这说明它本质上是**标签集合型单元格**，比“成员标签列”多了一层“多值聚合”的语义。

## 列级结构

```text
成员组标签列
├── 列头
│   └── 表头文字
└── 内容行 × N
    └── 单元/成员组标签
        └── 内容容器
            ├── 成员标签 × N
            ├── 组织 / 部门标签 × N
            └── 汇总标签（如 +9）× 0..1
```

## 抽离后的列级规范

### 1. 列头

> 通用列头样式（背景、分割线、padding、文字）见 `README.md#通用列头规范`。

### 2. 单元格外层

- 单元格左右 padding：`16px`
- 单元格上下 padding：`12px`
- 单元格底部分割线：`1px solid 场景/线条/kd-color-line-light`
- 单元格内容允许多行包裹
- 单元格内容采用 `flex-wrap` 组织，不是单行线性排列

结论：

- 该列不是固定高度内容块，而是**可换行标签集合列**
- 当标签数量变多时，单元格内容高度应可自然增长

### 3. 标签集合容器

当前样本内容区具有以下特征：

- 容器使用 `flex-wrap`
- 标签之间横向 / 纵向间距统一为 `8px`
- 外层内容容器宽度 fill 单元格
- 单元格中允许同时出现不同语义标签

这说明“成员组标签列”的核心不是某一个标签本身，而是**标签集合的排布规则**。

### 4. 成员标签

成员标签延续上一份 `成员标签列.md` 的模式：

- `KDAvatar` XS 头像
- 成员姓名文本
- `KDTag` 风格容器
- 标签背景：`场景/状态/kd-color-state-hover`
- 圆角：`4px`
- 内边距：`2px 6px`
- 内部 gap：`4px`

### 5. 组织 / 部门标签

当前样本中不仅有成员标签，也出现了“AI 研发部 / 采购部 / UX 组 / 人力资源部 / 成本预算组”等组织标签。

这类标签与成员标签的差异：

- 前置图标不是头像，而是 `16px` 组织 / 部门图标
- 文字仍然使用 `13px / 20px / 400 / text-primary`
- 仍然放在相同的标签容器里

结论：

- 组织标签和成员标签**共享同一标签容器规则**
- 区别只在于前置图标类型不同：
  - 成员：`Avatar XS`
  - 组织：`16px icon`

### 6. 汇总标签

当前样本出现 `+9` 汇总标签，说明存在“超出可展示数量”的折叠策略。

当前可抽离的稳定规则：

- 汇总标签与普通标签共享同一个容器样式
- 汇总标签内部只保留文本，不带头像或组织图标
- 汇总文本使用主文本色与 `13px / 20px / 400`

当前还不能直接抽死的规则：

- 何时开始折叠
- 最多显示几个标签后出现 `+N`
- `+N` 是否可点击展开

这些需要更多样本后再统一归纳。

## 可复用实现规则

### HTML / 前端实现建议

推荐结构：

```text
td
└── .cell-member-group-tags
    └── .member-group-tags
        ├── .member-group-tags__item--person
        ├── .member-group-tags__item--org
        └── .member-group-tags__item--summary
```

推荐样式语义：

- `.member-group-tags`
  - `display: flex`
  - `flex-wrap: wrap`
  - `gap: 8px`
  - `min-width: 0`
- 每个标签项统一沿用轻量 tag 容器样式

### 组件复用原则

- 成员项复用 `KDAvatar`
- 组织项复用语义图标资源或对应 KDIcon
- 标签壳层使用统一 `KDTag` 结构
- 汇总项 `+N` 不应另起一套特殊容器

## 与已有样本的关系

该样本与 `成员标签列.md` 的关系非常明确：

- `成员标签列.md`：单个成员标签单元格
- `成员组标签列.md`：多个成员 / 组织标签组成的集合单元格

因此可以得到一个中间判断：

- “成员标签列”更像**单元格内容原子模式**
- “成员组标签列”更像**单元格内容组合模式**

## 当前样本不应被误抽象的部分

以下信息暂不视为公共规范：

- 当前具体姓名 / 部门名称
- 当前 `+9` 的具体数量
- 哪些行是成员 + 组织混排，哪些行是纯成员
- 是否所有业务都允许头像与部门标签混排

这些都还需要更多业务样本验证。

## 当前判断

目前样本库已经具备一组可归纳趋势：

1. 图文列
2. 复选列
3. 成员标签列
4. 成员组标签列

其中第 3 和第 4 类已经明显属于“标签型单元格体系”。

如果后续再出现：

- 状态标签列
- 多标签列
- 可折叠标签列

就可以开始抽出一个更上层的 `标签型单元格规范.md`。
